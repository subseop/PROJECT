# 주제

주제는 재고의 관리가 어려운 중소상공인들을 위한 재고관리서비스로,
기본 crud, 대형마트와 차별화된 상품추천, 판매 기록 대시보드, 발주 상품 추천 등을 해주는 기능을 넣었다.


## 데이터베이스 기본 개념
1. 주키(PK)
 각 테이블에서 각 행을 유일하게 식별하는 값
  - 겹치면 안됨(중복x)
  - 비워둘 수 없음(NULL x)
  - 한 테이블에 보통 1개

2. 외래키(FK)
 다른 테이블의 PK를 참조하는 컬럼
  - 값은 참조되는 테이블(PK)에 반드시 존재해야 함
  - FK 자체는 중복 가능
  - 부모가 삭제되면 자식도 처리해야 하므로 ON DELETE CASCADE 같은 옵션을 둠
    
    외래키가 있는 쪽 = 참조하는 쪽(자식 테이블)
    외래키가 없는 쪽 = 참조를 당하는 쪽(부모 테이블)

3. 테이블 관계
 - 1:1 관계: 한쪽의 레코드가 다른 쪽의 한 레코드와만 연결되는 구조
 - 1:N 관계: 한쪽의 한 레코드가 다른 테이블의 여러 레코드와 연결되는 구조
 - N:N 관계: 여러 개가 여러 개와 연결될 수 있는 관계
   but, DB는 직접적인 N:N관계를 지원하지 않으므로 반드시 중간 테이블(연결 테이블)을 만들어야 함


## 테이블 구축
- STORE 테이블 구축
    ```
    -- 1) STORE
    CREATE TABLE store (
        store_id     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        store_name   VARCHAR2(100) NOT NULL
    );
    ```
    NUMBER: 모든 형태의 숫자 저장 가능
    GENERATED BY DEFAULT AS IDENTITY: Oracle에서 자동 증가 번호(1,2,3, ...)
    VARCHAR2: 문자열 String 타입

- STORE_PROFILE 테이블 구축
    ```
    -- 2) STORE_PROFILE  (STORE : STORE_PROFILE = 1 : 1, PK=FK)
    CREATE TABLE store_profile (
        store_id       NUMBER PRIMARY KEY,
        address        VARCHAR2(200),
        phone          VARCHAR2(30),
        opening_hours  VARCHAR2(100),
        CONSTRAINT fk_store_profile_store
            FOREIGN KEY (store_id)
            REFERENCES store (store_id)
            ON DELETE CASCADE
    );
    ```
    CONSTRAINT fk_store_profile_store: 제약조건과 그 이름
    FOREIGN KEY (store_id): store_id를 외래키로 지정
    REFERENCES store (store_id): 외래키가 참조하는 부모테이블과 컬럼 지정
    ON DELETE CASCADE: 부모 테이블(store)을 삭제하면, 그 행을 참조하던 자식 테이블 (store_profile) 도 같이 삭제하라

- PRODUCT 테이블 구축
    ```
    -- 3) PRODUCT
    CREATE TABLE product (
        product_id         NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        standard_name      VARCHAR2(120) NOT NULL,
        standard_category  VARCHAR2(80)  NOT NULL,
        is_active          CHAR(1) DEFAULT 'Y' NOT NULL,
        CONSTRAINT chk_product_is_active CHECK (is_active IN ('Y','N'))
    );
    ```
    CHECK (is_active IN ('Y','N')): is_active에는 Y, N 두 값만 가능

- LARGE_MART_PRODUCT 테이블 구축 
    ```
    -- 4) LARGE_MART_PRODUCT (외부 카탈로그)
    CREATE TABLE large_mart_product (
        lm_product_id  NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        product_name   VARCHAR2(120) NOT NULL,
        category       VARCHAR2(80)  NOT NULL
    );
    ```

- product_lm_map 테이블 구축(PRODUCT : LARGE_MART_PRODUCT = N : N (브릿지))
    ```
    -- 5) PRODUCT : LARGE_MART_PRODUCT = N : N (브릿지)
    CREATE TABLE product_lm_map (
        product_id     NUMBER NOT NULL,
        lm_product_id  NUMBER NOT NULL,
        CONSTRAINT pk_product_lm_map PRIMARY KEY (product_id, lm_product_id),
        CONSTRAINT fk_plm_product
            FOREIGN KEY (product_id) 
            REFERENCES product (product_id)
            ON DELETE CASCADE,
        CONSTRAINT fk_plm_lm
            FOREIGN KEY (lm_product_id)
            REFERENCES large_mart_product (lm_product_id)
            ON DELETE CASCADE
    );
    ```
    product_id와 lm_product_id 모두 주키로 설정하고 PRODUCT 테이블과 LARGE_MART_PRODUCT 테이블을 각각 참조함 
    -> 두 테이블 연결

- TIME_MONTH 테이블 구축
    ```
    -- 6) TIME_MONTH
    CREATE TABLE time_month (
        month_id     NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        year         NUMBER NOT NULL,
        month        NUMBER NOT NULL,
        month_label  VARCHAR2(20) NOT NULL,
        CONSTRAINT chk_time_month_mon CHECK (month BETWEEN 1 AND 12),
        CONSTRAINT uq_time_month UNIQUE (year, month)
    );
    ```
    CONSTRAINT uq_time_month UNIQUE (year, month): year, month 두 컬럼의 조합이 테이블에서 절대 중복될 수 없음
    ex) (2024, 1)이 중복될 수 없음

- MERCHANT_PRODUCT 테이블 구축
    ```
    -- 7) MERCHANT_PRODUCT (STORE : 1:N, PRODUCT : 1:N)
    CREATE TABLE merchant_product (
        merchant_product_id   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        store_id              NUMBER NOT NULL,
        product_id            NUMBER NOT NULL,
        merchant_product_name VARCHAR2(120),
        is_active             CHAR(1) DEFAULT 'Y' NOT NULL,
        CONSTRAINT chk_mp_is_active CHECK (is_active IN ('Y','N')),
        CONSTRAINT fk_mp_store
            FOREIGN KEY (store_id)
            REFERENCES store (store_id),
        CONSTRAINT fk_mp_product
            FOREIGN KEY (product_id)
            REFERENCES product (product_id),
        CONSTRAINT uq_mp_store_product UNIQUE (store_id, product_id)
    );
    ```

- SALES 테이블 구축
    ```
    -- 8) SALES  (MERCHANT_PRODUCT : 1:N, TIME_MONTH : 1:N)
    CREATE TABLE sales (
        sale_id             NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        merchant_product_id NUMBER NOT NULL,
        month_id            NUMBER NOT NULL,
        qty                 NUMBER(18,2) DEFAULT 0 NOT NULL,
        unit_price          NUMBER(18,2) DEFAULT 0 NOT NULL,
        -- Oracle 가상 컬럼(계산 컬럼)
        revenue             GENERATED ALWAYS AS (qty * unit_price) VIRTUAL,
        CONSTRAINT fk_sales_mp
            FOREIGN KEY (merchant_product_id)
            REFERENCES merchant_product (merchant_product_id),
        CONSTRAINT fk_sales_month
            FOREIGN KEY (month_id)
            REFERENCES time_month (month_id),
        CONSTRAINT uq_sales_mp_month UNIQUE (merchant_product_id, month_id),
        CONSTRAINT chk_sales_nonneg CHECK (qty >= 0 AND unit_price >= 0)
    );
    ```
    GENERATED ALWAYS AS (qty * unit_price): qyt와 unit_price의 곱이 revenue로 자동 저장, 직접 INSERT, DELETE 불가능
    VIRTUAL: 테이블에 실제로 데이터를 저장하지 않음, 조회할 때마다 직접 바로바로 계산해서 보여주는 방식
    UNIQUE (merchant_product_id, month_id): 한 점포의 상품에 대해, 한 달에 한줄만 존재
    CHECK (qty >= 0 AND unit_price >= 0): 음수 방지

### PREDICTION은 추후에 삭제될 수 있음
- PREDICTION 테이블 구축
    ```
    -- 9) PREDICTION (STORE/PRODUCT/TIME_MONTH 각각 1:N)
    CREATE TABLE prediction (
        prediction_id   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
        store_id        NUMBER NOT NULL,
        product_id      NUMBER NOT NULL,
        month_id        NUMBER NOT NULL,
        target          VARCHAR2(40) NOT NULL,      -- 예: 'qty', 'revenue'
        predicted_value NUMBER(18,4) NOT NULL,
        generated_at    TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
        CONSTRAINT fk_pred_store
            FOREIGN KEY (store_id)
            REFERENCES store (store_id),
        CONSTRAINT fk_pred_product
            FOREIGN KEY (product_id)
            REFERENCES product (product_id),
        CONSTRAINT fk_pred_month
            FOREIGN KEY (month_id)
            REFERENCES time_month (month_id),
        CONSTRAINT uq_prediction UNIQUE (store_id, product_id, month_id, target)
    );
    ```
    NUMBER(18,4): 자릿수와 소수 자릿수
    TIMESTAMP: 날짜 + 시간 + 밀리초까지 저장하는 타입 ex) 2025-12-06 04:28:15.123456
    DEFAULT SYSTIMESTAMP: 값을 직접 넣지 않으면, Oracle이 자동으로 지금 시각을 넣어줌, 
    SYSTIMESTAMP는 현재 DB 서버의 날짜·시간을 정확한 소수초까지 포함한 내장 함수

- FK 조인 성능요 보조 인덱스
    ```
    -- FK 조인 성능용 보조 인덱스
    -- (PK/UNIQUE는 자동으로 인덱스 생성됨)
    CREATE INDEX idx_store_profile_store_id ON store_profile (store_id);

    CREATE INDEX idx_mp_store_id    ON merchant_product (store_id);
    CREATE INDEX idx_mp_product_id  ON merchant_product (product_id);

    CREATE INDEX idx_sales_mp_id    ON sales (merchant_product_id);
    CREATE INDEX idx_sales_month_id ON sales (month_id);

    CREATE INDEX idx_pred_store_id   ON prediction (store_id);
    CREATE INDEX idx_pred_product_id ON prediction (product_id);
    CREATE INDEX idx_pred_month_id   ON prediction (month_id);

    CREATE INDEX idx_plm_lm_id       ON product_lm_map (lm_product_id);
    ```
    JOIN 성능 향상, 부모 테이블 삭제 시 자식 테이블 검증 느려짐 등을 이유로 FK에 인덱스 생성
    PK, UNIQUE에는 자동으로 인덱스가 생성됨
